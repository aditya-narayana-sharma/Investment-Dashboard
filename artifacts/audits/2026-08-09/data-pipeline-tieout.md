## Executive diagnosis

The architecture has several strong controls: server-only Kite calls; explicit cached/stale/unavailable states; exact Mail mailbox names; atomic Apple Health archive extraction; local-only podcast summarization by default; no-store API responses; formula tests for portfolio allocation, earnings, Health dates, sector factors, and FII/DII flows; and retention of last validated snapshots after failures.

However, the system is not decision-ready because several states labeled `live`, `verified`, or export-ready do not prove the full semantic contract:

1. Apple Health sums raw records across overlapping sources and groups sleep by start date, which can materially overstate or date-shift operational-day KPIs while still marking the snapshot `live`.
2. Earnings `verified` means only “reported rows have any HTTP URL and nonblank KPIs”; it does not verify IR/NSE primacy, source agreement, publication date, or overdue reported events.
3. yfinance end-of-day closes are labeled `live` and stamped with fetch time, even when only a subset of a sector universe is priced.
4. PDF export checks sector HTTP status but not each sector payload’s semantic status, and it uses the non-forcing content refresh path despite the “refresh immediately before export” contract.
5. The visual-overhaul commit adds hardcoded 6 Aug Axis trading calls that overwrite same-symbol refreshed trading-bucket calls regardless of publication recency.
6. Existing operational metadata is stale: the last saved startup audit failed Mail/Podcasts and Health; the current Health snapshot is stale through 5 Aug against an 8 Aug operational target.
