Orientation

What STRATJI is

"STRATJI" is your name for this platform; in the code it ships as the Investment Dashboard repo and self-brands as the "Portfolio Intelligence" Mac/iPhone app. (The literal string "STRATJI" does not appear anywhere in the repo — it's the working title, not a code identifier.)

It is a local-first, single-user research and portfolio cockpit. A private Flask/Waitress gateway serves the Next.js dashboard at http://localhost:5050/, and Tailscale Serve exposes it privately to your iPhone — never to the LAN or public internet. The Mac stays the application server: Kite credentials, Apple Mail, Podcasts, Health data and MCP calls all remain server-side. It fuses live Zerodha Kite broker state with Axis Research, newsletter and podcast digests, an earnings calendar, macro scenarios, and Apple Health — with a hard rule against ever presenting stale or fabricated data as live.

The same dashboard also renders the Portfolio Investment Brief you shared: it is produced by the app/report route and exported through app/api/report-pdf. So "generate future briefs like the one I provided" and "analyze this dashboard" are the same system — the brief is this platform's print artifact.

Under the hood

Architecture & stack

A React front end, a private Python serving shell, and a server-only data spine that reaches broker APIs and the Apple ecosystem — wrapped in native apps for the phone.

Front end
Next.js 16 on vinext (Cloudflare's Vite/RSC runtime) · React 19 · Recharts for donuts/radar/dials · lucide-react icons · Tailwind 4 · TypeScript. Dark "editorial" theme — black bands, Georgia serif headings, blue accents, green/amber/red semantics.
Serving shell
Flask + Waitress gateway (flask_gateway.py) bound to localhost:5050, run as a macOS background job; Tailscale Serve for private mobile access. Isolated .venv-flask. Optional Cloudflare D1/R2 bindings via .openai/hosting.json; Drizzle ORM present (schema currently empty).
Data spine
Server-only Kite MCP session (the adjacent Go kite-mcp-server, auto-started) reads holdings, positions, orders, GTTs, margins. /api/kite/snapshot refreshes on load and every 5 minutes. Holdings are the critical read; secondary endpoints are failure-tolerant so one blank feed can't wipe the portfolio.
Research feeds
Apple ecosystem via Computer-Use / osascript: Mail (iCloud → Newsletters & Axis Research only), Podcasts, Calendar, Reminders (Job 🔍 / Earnings), Notes (Health Daily), Apple Health (HealthKit export ZIP). Plus sector snapshots & benchmarks, yfinance quote fallback, and a Firecrawl web layer.
Native apps
SwiftUI iOS/macOS wrapper (apple-app/) around one persistent WKWebView: onboarding, source/connection freshness, operational-day HealthKit upload (single-use pairing token), offline recovery, PDF sharing. Safari PWA is the fallback install path.
Integrity
A mandatory startup refresh audit (scripts/refresh-dashboard-data.sh) validates payload semantics — Kite/sectors status=live, earnings verified, Health live to an 8 PM IST operational date. Failures surface as Stale / Cached / Unavailable in a compact freshness strip, never as fake live values.

Inputs

Live sources & freshness rules

The dashboard treats itself as "current" only after every source independently passes the startup audit; anything else is labelled and named.

Kite — holdings · positions · orders · GTTs · margins · P&L Apple Mail — iCloud Newsletters + Axis Research Apple Podcasts — transcripts / descriptions Apple Calendar — earnings + all events Apple Reminders — Job 🔍 · Earnings Apple Notes — Health Daily Apple Health — HealthKit export Sectors — snapshots + benchmarks yfinance — quote fallback Firecrawl / web
Two rules that shape everything

No fabrication: failed live values are never silently replaced with static ones — they show Stale/Cached/Unavailable with the failing source named. Health 8 PM policy: healthTargetDate(nowIST) rolls to day D at 20:00, holds through 01:59, and uses D-1 from 02:00–19:59, so comparisons are always anchored to a defined operational date.
